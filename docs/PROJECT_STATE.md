## Работа

`start-dev.bat` — разработка, `start-local.bat` — production-просмотр по `http://127.0.0.1:3000`.
Для воспроизводимой установки используйте `npm ci`.
Проверки: `npm test`, `npm run lint`, `npm run typecheck`, `npm run build`.
GitHub Actions проверяет код и публикует static export в GitHub Pages при push в `main`.

После обновления телефона закройте все окна PWA и откройте снова, либо примените предложенное обновление. Для общей базы войдите в один аккаунт Supabase на всех устройствах.

## Выполненные доработки

## Постоянный разговорный чат — 27 октября

Модальное окно помощника заменено постоянной правой колонкой на широком локальном экране и сворачиваемой нижней панелью на узком. Модель фиксирована: `qwen3.5:9b`. Единый API-режим `conversation` отвечает на вопросы и готовит действия по естественным сообщениям; история передаётся для продолжения разговора. Применение и отмена доступны фразами «да, применяй» / «не надо» и кнопками внутри переписки.

История хранится локально по аккаунту в `dnevnik.chat.v1.*`; старые неподтверждённые планы после перезапуска не активируются. Новый запрос отменяет предыдущий план. Смена раздела сохраняет разговор, каждое сообщение получает актуальные записи и проекты. Окно быстрого ввода не открывается при восстановлении черновика: он остаётся под кнопкой «Продолжить».

На публичной PWA чат к локальной Ollama не подключается; доступен на компьютере через единый ярлык. Телефон продолжает обмен записями через Supabase. Настоящая Qwen3.5:9b проверена на вопросе о покупках и следующей команде отметить названную покупку выполненной, без записи в рабочую базу.

Проверки постоянного чата: 176 unit-тестов, ESLint, TypeScript/production build; отдельный браузерный сценарий вопросов, продолжения диалога, подтверждения фразой, диктовки, восстановления черновика без модального окна, сохранения истории и очистки только переписки. Пять axe-проверок на широком/узком экране и в тёмной теме — без нарушений. Приватный сценарий: .maintenance/chat-panel-check.mjs; снимки: .maintenance/qa-conversation-2026-10-27/.

## Исправление микрофона чата — 27 октября

После сообщения о неработающем микрофоне браузерный SpeechRecognition в чате заменён на реальную запись MediaRecorder и локальную расшифровку faster-whisper 1.2.1 (base, CPU int8). Добавлены явные стадии разрешения/записи/расшифровки, таймер, измеритель уровня, выбор входа, понятные ошибки, прослушивание и повтор без потери записанного аудио. API /api/local-speech принимает только локальный origin, ограничивает размер и время, не допускает параллельной загрузки CPU и удаляет временные записи.

Движок и модель установлены отдельно внутри .maintenance/speech-runtime; ничего из них не публикуется. Исходники и воспроизводимый установщик — scripts/transcribe-local.py, scripts/setup-local-speech.ps1, scripts/requirements-local-speech.txt. На обычном запуске нет загрузки моделей, во время распознавания сеть Whisper отключена.

Проверено: 181 unit-тест; настоящий MediaRecorder записал синтетическую русскую звуковую дорожку, endpoint локально расшифровал числа и молоко, текст попал в разговор. Проверены отказ разрешения, занятый микрофон, сохранение аудио после ошибки и повтор, тишина возвращает 422 без выдуманного текста, чужой origin получает 403. Физический микрофон пользователя не захватывался; открытые окна его браузера не управлялись. Приватные тесты: .maintenance/local-voice-check.mjs и .maintenance/voice-errors-check.mjs.
